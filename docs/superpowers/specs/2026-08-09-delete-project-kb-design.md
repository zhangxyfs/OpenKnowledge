# 删除项目知识库（GUI 其他页，三重确认）设计

日期：2026-08-09 · 状态：已批准 · 目标版本：v2.9.0（拟定）

## 背景与目标

GUI「其他」页缺少删除某个项目知识库的入口。知识库数据（`~/.openknowledge/projects/<name>/`：knowledge/、kb.db、INDEX.md、config.toml、state/）一旦误删不可恢复，因此删除必须有多重确认，不能随手点掉。

已确认的决策：
- 删除语义：**物理删除**（注销注册表 + 删除项目目录）；不采用回收站/只注销方案
- 备份策略：确认弹窗内「删除前先导出 zip 备份」勾选框，**默认勾选**，可主动取消
- 确认形式：**勾选「我已了解后果」+ 手动输入完整项目名**，两者齐备删除按钮才解锁

## 范围

- 删除内容：注册表项目条目（`registry.toml`）+ `~/.openknowledge/projects/<name>/` 整个目录
- 明确不动：项目源码目录（`paths` 指向的仓库）；全局配置、其他项目数据
- 仅 GUI 提供入口；CLI 不加子命令（YAGNI）

## 前端（web/）

### 其他页危险卡

- 新增「删除项目知识库」卡片，复用既有 `.card-danger` 样式（红边浅红底）
- 内容：项目下拉（复用状态里的项目列表，**不含**导出卡的「全部项目」项）+「删除…」按钮（`.btn-danger`）
- 项目列表随 `refreshStatus()` 同步渲染（与导出卡同一数据源）

### 确认弹窗（复用 `.modal` 模式，新 id）

按顺序包含：

1. **影响面明示**：「将永久删除项目 **X** 的知识库：共 N 条知识（含 M 条草稿）、索引、项目配置，并注销注册表（hooks 不再注入）。项目源码目录不受影响。」
   - N/M 在打开弹窗时通过现有 `GET /api/entries?project=X` 统计（含草稿计数）；加载失败时显示「条目统计失败」且不阻塞后续确认
2. 「删除前先导出 zip 备份」勾选框（**默认勾选**）
3. 「我已了解后果，此操作不可撤销」勾选框（默认不勾）
4. 输入框：「请输入完整项目名 X 以确认」——与项目名**精确匹配**（大小写敏感，不去空格以外的字符；输入首尾空格 trim 后比较）
5. 按钮区：「永久删除」（`.btn-danger`，初始 `disabled`）+「取消」

解锁条件：③ 勾选 **且** ④ 输入精确匹配项目名。②（备份）不参与解锁。

### 执行流程

1. 勾选备份 → 先触发 `GET /api/export?project=X` 浏览器下载（复用导出卡的下载方式）；导出请求失败 → 中止，错误横幅提示「备份失败，已中止删除」
2. `DELETE /api/project?project=X`
3. 删除期间删除按钮 loading 态（`删除中…` + disabled），防重复点击
4. 成功后关闭弹窗 → `refreshStatus()` 全量刷新；若删的是当前管理页选中项目，`renderProjectSelect` 现有逻辑自动切到下一个项目（无项目时管理 tab 自动隐藏，现有逻辑已覆盖）
5. 响应带 `warning` 字段时（目录残留），错误横幅提示「已注销，但目录删除失败，请手动清理 <路径>」

## 后端

### registry 包

- 新增 `RemoveProject(name string) bool`：按名移除并返回是否找到（仿 `AddProject` 模式，纯内存操作，持久化走既有 `Save`）

### DELETE /api/project

- 路由：`DELETE /api/project?project=<name>`，挂 `withAuth`（与既有写操作一致）
- 流程：
  1. 缺参 → 400；未注册 → 404
  2. **先注销**：`RemoveProject(name)` + `Save`；Save 失败 → 500 中止（目录不动，数据不丢）
  3. **再删目录**：`os.RemoveAll(<home>/projects/<name>)`；失败 → 返回 200 + `{"ok":true,"warning":"目录删除失败: ...","dir":"<路径>"}`（已注销，残留可手动清理）
  4. 成功 → 200 `{"ok":true}`
- 安全：目录名取注册表匹配后的 `p.Name`（非用户原始输入），拼接在 `registry.Home()/projects/` 下，无路径穿越面

顺序理由：先注销后删目录，失败兜底方向是「数据残留可手动清」，而非「数据已删注册表还指着它」。

## 错误处理

- 条目统计失败 → 弹窗内提示，不阻塞
- 导出失败 → 中止删除，横幅提示
- Save/RemoveAll 失败 → 按上述后端语义；前端横幅展示
- 全部失败路径都不影响其他项目数据

## 测试

### Go（internal/gui/api_test.go、internal/registry）

- `RemoveProject`：存在移除返回 true、不存在返回 false、Save 往返后注册表不含该项
- `DELETE /api/project`：
  - 正常：临时 OK_HOME 造项目（knowledge 下两条目）→ 调用后目录不存在、registry.toml 不含该项目、`/api/status` projects 无该项目
  - 未注册 → 404；缺参 → 400
  - 无 token/错 token → 401（既有 withAuth 用例模式）

### 前端（手动验证清单）

- 解锁逻辑：仅勾选、仅输名、输名大小写不符/多空格 → 按钮均保持 disabled；齐备才解锁
- 默认勾备份 → 删除时先下载 zip 再删
- 取消勾备份 → 直接删
- 删当前选中项目 → 下拉与条目列表自动切到下一项目
- 删最后一个项目 → 管理 tab 隐藏，落引导页

## 非目标

- 回收站/软删除、定期清理
- CLI 删除子命令
- 批量删除
- 删除项目的全局性副作用（如同时清理其他机器同步副本）——不存在该概念
