# 跨轮注入冷却 + 优化链路加固

> 检索注入长出跨轮记忆：同一会话里注入过的条目冷却 N 轮不再重复注入，省下的预算让给新条目；条目 AI 优化对推理模型的一批实战问题一并修实。

## 新功能

- **跨轮注入冷却**（`retrieve.dedup_turns`，默认 3）：连续追问同一主题时，同一条目不再每轮以相同名次反复注入——冷却期内自动跳过，到期自然回归。冷却中的条目不占 top_n 名额（排名靠后的新条目补位）；「继续」「好的」这类泛化 prompt 轮同样消耗冷却轮次；上下文压缩后冷却台账一并重置（指针已被摘要掉，条目立即可再注入）；冷却期内模型按历史指针读取该文件仍记为采纳，反馈降权统计不被污染。GUI 引导页新增「跨轮注入冷却」卡（0~99，0=关闭）；冷却跳过记 ok.log，GUI 日志页按「冷却」过滤，`ok search` 与 GUI 搜索不受冷却影响（诊断看全量）。

## 改进

- **优化输出上限可配**：模型配置卡新增「最大 token」单字段保存（0=默认 8192，或 1024~131072），只改这一项、不动 temperature 等其他高级参数；无使用中配置时提示先设「使用中」。
- **事实检索命中窗口**：AI 优化的参照检索按正文反引号代码片段定位，摘录标识符所在行窗口而非只看文件头，参照更贴上下文。
- **token 消耗透明**：每次优化的对照弹窗展示本次入/出 token 消耗；「无需优化」的判定放宽为语义级相同（全半角、CJK 标点、空白与连续点号归一），排版级改写不再弹出对照。
- **GUI 安全加固**：项目名做形状校验（拒绝路径穿越段名），浏览器打开外链前校验 URL 安全性。

## 修复

- **推理模型优化结果为空**：思考过程与正文共享同一 max_tokens 预算，默认 4096 会被长思考烧穿——正文为空、completion 钉在上限。默认上限提到 8192；个别把答案 JSON 整个吐进思考过程、正文留空的模型，从思考内容兜底提取。
- **截断误报解析失败**：输出触顶 max_tokens 被截断时不再笼统报「非合法 JSON」，明确提示到「引导页 → 模型配置」调大最大 token（部分网关不回 finish 标记，按 completion 打满上限双信号判定）。

## 说明

- 冷却升级后默认开启（3 轮），不合适可在引导页或 config.toml 设 `dedup_turns = 0` 完整恢复旧行为；新会话天然无冷却。
- 无接口破坏，直接覆盖升级即可。
