# v2.19.0 条目 AI 优化 + 模型配置

> GUI 长出「AI 优化条目」能力：配上模型服务后，编辑条目时一键据实润色，逐字段对照确认再落盘。日志页大文件轮询卡顿一并治理。

## 新功能

- **模型配置**：引导页新增「模型配置」卡，管理跨项目共用的生成模型服务（OpenAI 兼容 / Anthropic 兼容两种协议）。卡片列表 + 行内展开编辑，支持添加、同名覆盖、设为使用中、删除、连通性测试；api_key 掩码回显，掩码或留空提交即保留原值。
- **条目 AI 优化**：管理页编辑弹窗新增「✨ 优化」。先做事实检索——按正文里的代码引用读取项目真实代码片段（合计 ≤3000 token）、混合检索知识库相关条目 top3、摘录 INDEX——再连同条目现状一起发给模型，按「参照优先、不杜撰、最简洁不丢重点」的纪律优化标题/tags/摘要/正文（类型与 mandatory 锁死不动）。
- **对照预览回填**：优化结果先弹对照预览，逐字段展示原数据与优化后内容；每张字段卡有独立「回填」按钮可只更新单个字段，底部「回填表单」全量回填。回填只写表单，点「保存」才写入 .md——优化接口本身绝不落盘。
- **高级参数**：模型配置卡里「高级」展开 temperature 与 max_tokens 可选覆盖。temperature 留空即不传（服务端默认），专治锁死参数值的模型；max_tokens 为 0 用调用方默认。

## 改进

- **无需优化判定**：模型自报或逐字段比对与原文相同时，直接蓝色横幅提示「无需优化」，不再弹同义改写级的对照预览。
- **优化可取消**：优化进行中关闭编辑弹窗即中断请求，服务端随连接断开同步取消，不白跑模型调用。
- **优化过程可审计**：每次优化的开始、模型思考过程（reasoning_content / thinking 块）、原始回答与结果判定（ok / no_change / 失败原因）截断后落 `ok.log`，GUI 日志页自动可见。
- **日志页轮询提速**：自动刷新改为带 size-mtime 签名轮询，日志文件无变化时服务端只回几十字节的 unchanged，不再每 2 秒重读大文件、整包传输、全量重绘。

## 修复

- **优化默认超时过短**：生成调用 HTTP 超时从 30 秒提到 120 秒（`[llm] timeout_sec` 显式配置仍优先），修复大 prompt 下「awaiting headers」超时。
- **Kimi 等模型 400**：不再写死 temperature=0.3，缺省不传由服务端默认值接管。
- 模型配置卡头兼容徽标随类型下拉实时切换。

## 说明

- 升级后如需 AI 优化：引导页「模型配置」配好服务并设为使用中即可；未配置时点优化会引导跳转配置。
- 无接口破坏，直接覆盖升级即可。
