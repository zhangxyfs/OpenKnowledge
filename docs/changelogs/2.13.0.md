# 2.13.0

## 新功能
- 新增 qoder 适配器（第八个 AI 助手集成）：合并写 `~/.qoder-cn/settings.json`
  的 `hooks` 分组（备份 + 幂等 + 第三方条目保留），hook 契约逐字兼容 Claude Code——
  经官方 hooks-reference 文档与 `@qodercn-ai/qoderclicn` 1.1.20 bundle 源码双向核实
  （stdin JSON 同字段、退出码 0/2、注入 `hookSpecificOutput.additionalContext`、
  Stop `decision:block`），输出协议零改动复用；PostToolUse 追 `Write|Edit`
  （Qoder 与 Claude 同款写盘工具），auto 自省与 enforce 规则与 Claude 同档；
  技能零适配——Qoder 用户级技能目录 `<配置目录>/skills`，SKILL.md 格式与 Claude
  逐字一致（本机 bundled skills 实证），现有共享模板直接分发
- 安装/自愈自动开启 `hooksConfig.enabled` 开关——bundle 源码实证 Qoder 对
  `hooksConfig.enabled` 未显式设置时默认关闭（`enableHooks = !disableAllHooks &&
  hooksConfig.enabled`，settings schema 默认 `{}`），不开则 hooks 装好也静默不派发
  （codex 特性开关同款教训）；`HooksInstalled` 判定与自愈均纳入开关状态；卸载不关闭
  （关掉会连带停掉用户第三方 hooks）；用户级 `disableAllHooks` kill switch 不读取不修改
- Windows 下 hook 命令为 `ok-hook-*.cmd` 包装文件裸路径（Qoder 经 `cmd.exe /d /s /c`
  执行 command 型 hook，`/s` 剥首尾引号、quoted 命令串静默不执行——codex #38168 同源
  问题）；settings.json 与 exe 解耦，迁移自愈只改包装内容、settings.json 逐字节不动
- 引导页/`ok setup`/`ok doctor`/卸载清理经注册表自动纳入 qoder（`QoderHome()` 优先级：
  `OK_QODER_HOME` 测试口 > `QODERCN_CONFIG_DIR` 官方重定位 > `~/.qoder-cn`）
- 新增 qoder-ide 适配器（第九个 AI 助手集成，Qoder CN IDE 灵码内核面）：合并写
  `~/.lingma/settings.json` 的 hooks 分组（备份 + 幂等 + 第三方条目保留），hook 契约
  与 CLI 同构但**能力降级**——IDE 仅 5 事件且 Stop/PostToolUse 不可阻断（官方 IDE
  hooks 文档核实）：注入（UserPromptSubmit additionalContext）与触碰追踪
  （PostToolUse Write|Edit）可用，enforce/auto 自省降级（Stop 的 decision:block 被
  忽略、静默放行）；无 enabled 门；改配置需重启 IDE 生效（无热加载）；技能进
  `~/.lingma/skills`（IDE 与 CLI 技能目录不同）。PostToolUse matcher 用无空格
  `Write|Edit`——在 IDE "| 拆分"与"正则"两种匹配语义下均正确；IDE 工具名双套
  （原生 run_in_terminal/create_file/search_replace ↔ 兼容 Bash/Write/Edit 运行时映射）
- 全量测试补齐 `OK_QODER_HOME`/`OK_QODER_IDE_HOME` 隔离（13 个测试文件），GUI status
  断言同步 9 个 agent
- 测试套件 Linux 可移植：agentx/setupx 的 7 个测试文件消除 Windows 夹具硬编码
  （ToSlash 期望改随平台分叉、.cmd 案例 want 按 GOOS 计算、包装文件断言仅 Windows、
  exe 迁移语义按平台分叉——Windows 断言"逐字节不动"，quoted 形态平台断言"必然重写
  且无旧路径残留/信任重算一致"）；WSL（Ubuntu 22.04 + Go 1.25）全量 `go test ./...`
  双平台回归均绿
