# v2.18.0 索引治理与并发加固：INDEX 预算渲染 + 条目归档 + SQLite WAL

> 核心变化：知识库变大后 INDEX.md 不再全量罗列——按价值排序、超限折叠、摘要
> 去重，把有限的注入预算留给高价值条目；新增条目归档生命周期（`ok archive`）；
> 并发加固一批——SQLite 开 WAL 修掉并发下注入静默跳过，注册表与会话状态的
> 写路径全部收口跨进程文件锁。

## 新功能

- **INDEX 预算感知渲染**：`INDEX.md`（每轮注入的知识目录）从按文件名全量列出
  改为按价值排序——30 天窗口内「采纳 ×2 + 注入 ×1」计分，同分按最近编辑优先，
  草稿沉底；`[index] max_lines`（默认 50）超限时尾部折叠为一行「另有 N 条可用
  检索命中」提示，替代原先外层 token 截断的静默丢失；渲染层自动省略与标题
  重复的摘要。知识库持续增长时注入体积不再失控。
- **条目归档生命周期**：条目 frontmatter 新增 `archived` 字段——归档后不进
  INDEX 主列表与 Wiki 目录，仍留库可被关键词/向量检索命中；`ok archive <标题>`
  归档、`ok archive --undo` 恢复；`ok index` 重建索引时附带「归档候选」报告
  （按新 `created` 字段找长期无人问津的老条目），帮你定期给知识库瘦身。

## 修复

- **并发下注入静默跳过**：多个 agent 会话并发时，一进程持索引库写事务会把另一
  进程的注入查询挡到超时，整轮注入被静默跳过（知识库悄悄漏条目）。索引库改
  WAL 模式（读写互不挡），从根上消除。
- **注册表并发写丢项目**：`ok init`、GUI 删除项目、备份恢复三路并发写注册表时
  互相覆盖，项目注册静默丢失、hooks 对该项目失效。全部写路径收口为跨进程
  文件锁内的读-改-写。
- **会话状态写竞态收紧**：锁实现抽为公共原语——持锁崩溃残留 2 秒即可被抢占、
  等锁 5 秒失败降级执行（绝不卡死 agent 会话）、只删自己的锁；损坏的会话状态
  文件按空状态处理，防半截 JSON 被"洗白"回写。
- **daemon 转发超时双执行**：转发给 daemon 的请求超时后不再本地兜底重做一次，
  同一操作只执行一遍。

## 说明

- 老库打开自动迁移（archived 列、WAL 模式），无需手工操作；WAL 下 kb.db 旁会
  出现 `-wal`/`-shm` 伴随文件，属正常现象——kb.db 本就是派生索引，备份导出的
  是 knowledge/ 源文件，伴随文件无需也不应备份。
- 工程面：新增 Windows/Linux 双平台 CI（vet + build + 全量测试）；发布脚本支持
  断点续传（同名产物跳过、release 已存在自动复用）。
