# v2.16.0 检索注入按通道准入 + GUI 实时日志页

> 核心变化：UserPromptSubmit 不再注入与提问无关的知识——检索准入重构 + 语义门槛模型无关化；
  GUI 新增第四标签「日志」，实时查看 ok/守护/embedding 三来源日志。

- **检索准入重构（宁缺毋滥，不强行凑 top_n）**：
  - 准入与排序分离：总分 `α·BM25 + β·cos` 只用于排序；准入按通道独立判定——
    关键词通道归一 BM25 分（未乘 α）≥ 阈值 或 语义通道余弦 ≥ 语义门槛，满足其一才注入；
  - 新增 `retrieve.min_score`（默认 0.5，≤0 关闭），阈值随库规模缩放（<10 条关闭、
    10→30 线性过渡、≥30 取全值）——FTS5 bm25 的 idf 在小库下塌缩（N=2 时恰为 0），
    固定绝对阈值会误伤小库真实命中；
  - 新增 `retrieve.min_gap`（默认 0.25，≤0 关闭 gap 判定）：语义门槛改为模型无关——
    以本次查询余弦分布为参照，头部相对中位数有显著分离才启用 median+0.5·gap，
    无头部则语义通道整体不准入。四模型标定（bge-m3 / bge-large-zh-v1.5 /
    Qwen3-Embedding-8B / qwen3-emb-0.6b）× 12 场景全部按期望准入/拒绝；
    低对比度自定义 embedding 模型调低 min_gap 即可放宽；
  - 语义诊断不再静默：语义通道全部候选被拒时写 `prompt semantic` 日志（样本数/
    max/median/relGap），`ok search` 同步提示调节指引；
  - 语义检索退化（模型身份缺失/切换）时，注入末尾每会话一次附
    `[OpenKnowledge] 语义检索退化：…` 提示（原来只闷在 ok.log）。
- **GUI「日志」页（管理/引导/其他之后的第四标签）**：
  - `GET /api/logs` 回读 ok.log / daemon.log / embed-sidecar.log 尾部（每文件 ≤256KB，
    tail 参数可调），行带来源与 semantic 标记；
  - 2 秒轮询（仅标签激活）、来源 chips 多选（ok/守护/sidecar）+「仅语义」开关 +
    文本过滤输入框，用户上滚时暂停自动贴底；只读。
- **实测**：问"我已经验证了A…deepseek apiKey"零注入；"多-Agent支持 十个适配器"精确命中；
  "帮我写一个 python 爬虫"零注入。
- **测试**：新增 TestMinScoreFloor / TestSemanticFloor（min_gap 用例）/
  TestQueryChannelAdmission / TestQueryExSemanticRejected / TestSemanticRejectLog /
  TestAPILogs；全仓 `go test ./...` 26 包绿。
