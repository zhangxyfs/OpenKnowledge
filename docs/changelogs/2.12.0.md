# 2.12.0

## 新功能
- 新增 codex 适配器（第七个 AI 助手集成）：合并写 `~/.codex/hooks.json`
  （备份 + 幂等 + 第三方条目保留），hook 契约逐字兼容 Claude Code——注入
  `hookSpecificOutput.additionalContext`、Stop `decision:block`，输出协议零改动
  复用；写盘追踪解析 apply_patch 补丁头（`*** Add File:` / `*** Update File:` /
  `*** Delete File:` / `*** Move to:`），auto 自省与 enforce 规则与 Claude 同档；
  技能零适配——Codex 原生扫描共享 `~/.agents/skills`。注意 Codex 信任门：安装后
  首次运行会提示审查信任 hooks（`/hooks` 管理），exe 迁移自愈重写后会再次询问
- 安装时自动开启 Codex hooks 特性开关（0.118 起该特性为 under-development、默认关闭，
  不开则 hooks 静默不派发）——行级手术编辑 config.toml `[features] codex_hooks = true`，
  备份且其余内容逐字节保留；`HooksInstalled` 判定与自愈均纳入开关状态
- 安装/自愈自动写入 hooks.state 信任记录（trusted_hash 按 Codex 归一化身份的 canonical
  JSON SHA-256 计算，经源码与本机记录双向验证）——此前 hooks.json 内容任何变化
  （exe 迁移/重装/自愈）都会让信任过期、Codex 各前端静默跳过全部 hook 且无任何提示
- Windows 下 hook 命令改为 `ok-hook-*.cmd` 包装文件裸路径（规避 Codex 外层引号 bug——
  内嵌引号命令静默不执行却报 Completed，openai/codex#38168）；hooks.json 与 exe 解耦，
  迁移不再破信任；识别兼容旧 quoted 形态可平滑迁移
- 版本矩阵实证：codex exec 不派发 hooks；桌面端 26.707 与 CLI 0.147.0 在三修复
  （特性+信任+包装）后均实证可用——早期「26.707 不派发」判断系信任过期静默跳过的
  误判，派发在 26.707 已存在；Stop 在 0.147 实证派发（#38213 已修复）
- GUI 引导页新增 Codex 专属"信任门说明"按钮（特性开关/信任流程/重启生效四点说明）
