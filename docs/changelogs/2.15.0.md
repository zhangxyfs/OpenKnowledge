# v2.15.0 dsh 适配器：DeepSeek Harness 集成（第十个 agent，本地 JS 插件 + file:// URL 挂载）

> 说明：DeepSeek Harness（`dsh`）为 developer preview，明确声明可能有破坏性变更；适配器走本地插件挂载，不发布 npm 包。

- **新增 dsh 适配器（第十个 AI 助手集成，DeepSeek Harness）**：
  - 无 Claude 式 hooks 配置字段，走**本地 JS 插件**——go:embed 模板写入
    `$DSH_HOME/plugins/openknowledge/index.js`（头标记 + sha256 指纹管理幂等/自愈），
    再往家目录级 `$DSH_HOME/cordis.patch.yml` 插入标记块挂载行
    `- insert: [{ id: ok-hooks, name: '<file:///...>' }]`（家目录级所有 profile 共享）。
  - 插件三事件直订 Cordis 总线：`agent/pre-step`（waterfall，检索注入）≈ UserPromptSubmit、
    `tools/post-execute`（write|edit 追踪）≈ PostToolUse、`agent/turn-stopping`
    （exit 2 + stderr → `agent.steer()` 续跑）≈ Stop；子进程 `node:child_process.execFile`
    直 exec（无 shell 层，天然免疫 Windows pwsh 引号问题，且不经 workspace-write 沙箱执行器）。
  - 家目录解析：`OK_DSH_HOME`（测试隔离口）> `DSH_HOME`（官方重定位）> `~/.dsh`。
  - 技能零适配：DSH 原生扫描 `~/.agents/skills`，`SkillsDir()` 返回共享目录。
- **实机验证**：真实 DeepSeek API 会话端到端打通 prompt（注入）/ post-tool（触碰追踪）/
  stop（`stop_count` 递增）三事件；关键坑——vendored cordis loader 把 patch 的 `name`
  直接交给 Node ESM `import()`，Windows 盘符绝对路径报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`，
  必须 `file:///` URL 挂载。
- **测试**：`internal/agentx/deepharness_test.go` 12 用例（Detect/Install 幂等/保留第三方/
  Remove 往返/Ensure 自愈/SkillsDir）；全仓 7 个注册表遍历测试文件补 `OK_DSH_HOME` 隔离
  （20 处），`gui` agent 计数 9→10；全仓 `go test ./...` 26 包绿。
