# 2.21.0 wiki 基线读时继承（新分支自动继承可达基线，GUI 分支上下文状态卡）

- **问题**：游标按分支存储且只在 `ok wiki mark` 时归入当时所在分支，从 master 切出 `feat/x` 后第一次提问即注入「当前分支 feat/x 尚无基线」——但 master 游标 commit 必然是新分支 HEAD 的祖先，wiki 基线在该时点依然为真，`no_cursor` 把「能证明为真」与「不能证明」混为一档；真正的损失是落后追踪缺失，新分支积累 N 个 commit 后无人提醒 wiki 该更新。
- **修复**：
  - 检测层（internal/wiki，保持只读）：本分支无游标时 `CheckStatus` 读时回退——先验基准分支游标 commit 是否为 HEAD 祖先（一次 merge-base 短路），不命中再遍历其余游标取可达且 rev-list 距离最近者；命中 → `BranchState = "inherited"`、`InheritedFrom` 记录来源分支，`Behind`/`Stale` 照 ok 路径正常门控；全部不可达（如游离历史切出）维持 `no_cursor`。继承只是检测态，`wiki.json` 零写入、零迁移，游标写入仍只有 `ok wiki mark` 一个入口。
  - hook 注入：`wikiContextLine` 新增 `inherited` 分支——未超阈值注入「wiki 基于 master@abc1234；当前分支 feat/x 继承该基线」；超阈值合并为一行带落后数「（当前分支 feat/x 继承，落后 N commit）…建议更新」，同时 `wikiNudge` 的 stale 分支跳过避免同语义两行重复提醒；`no_cursor` 文案保留仅服务真无基线场景。
  - CLI：`ok wiki status` 的 inherited 态用键值块单列继承来源「基线: 继承自 master@127cc01（生成时间，条目数）」，超阈值时附「→ 建议在本分支运行 /openknowledge-wiki」。
  - GUI：分支上下文从一行文字升级为状态卡——branch-info 端点透传 `branch_state`/`inherited_from`/`behind`/`last_commit`/`generated_at`/`entry_count`；工具栏摘要超阈值加「wiki 落后 N」中性绿徽标；卡片展示基准分支/当前分支/继承基线/生成时间·条目数/落后数，并提供「在本分支更新 wiki」（复制引导文案）与「查看分支差异」两个动作入口；CheckStatus 失败 fail-open 退回现状一行文字。
- **验证**：按 spec §10 验收——切新分支首问注入「继承该基线」（TestCheckStatusInherited/TestPromptWikiInheritedContextLine 覆盖）；超阈值上下文行带落后数且无第二行重复提醒（TestPromptWikiInheritedStaleMergedLine 覆盖）；游离历史切出仍「尚无基线」（TestCheckStatusNoCursor）；基准分支注入逐字节不变（TestPromptWikiNoContextOnBaseBranch 及现有 hook 测试全绿）；wiki.json 继承路径零写入（git status 核对注入后 state 目录无变更）；GUI 状态卡人工核对为遗留项。
- **测试**：`TestCheckStatusInherited`（基准短路命中 inherited）/`TestCheckStatusInheritedPrefersBase`（基准可达时优先）/`TestCheckStatusInheritedFallbackNearest`（基准不可达取最近可达游标）/`TestCheckStatusNoCursor`（全部不可达维持 no_cursor）/`TestPromptWikiInheritedContextLine`（未超阈值文案）/`TestPromptWikiInheritedStaleMergedLine`（超阈值合并行 + nudge 去重）/`TestWikiStatusInheritedFrom`（CLI 键值块）/`TestBranchInfoAPI`（端点字段透传）；既有 ok/diverged/gone/legacy_orphan 路径测试全绿；全仓 `go test ./...` 绿、`go vet ./...` 无输出。
- **升级注意**：无行为回退风险——基准分支与无 wiki 场景注入逐字节不变；仅新切分支的注入文案从「尚无基线」变为「继承该基线」，GUI 分支上下文多一张状态卡。
