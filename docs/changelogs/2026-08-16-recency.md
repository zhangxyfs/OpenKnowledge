# 2026-08-16 时效信号：按 mtime 新鲜度给融合分乘系数（retrieve.recency）

- **问题**：零时效信号——两年前的过时 pitfall 与上周的 rule 同分竞争 top_n=2 的注入名额。
- **修复**：
  - `recency.Factor`：age ≤ fresh_days → 1.0，age ≥ stale_days → floor（默认
    0.85），中间线性；按条目类型分窗（[retrieve.recency.windows]：
    pitfall [90,365] / note [60,180] / rule、reference [180,730]）；
  - 作用位置：融合分（RRF/weighted 均在）之后乘系数、**不参与准入**——陈旧
    不等于无关，陈旧条目仍可准入注入，只在近似同分时让位；RRF 名次尺度下
    0.85 足以翻转相邻名次而不可能翻越大分差（温和决胜）；
  - 信号源 `entries.mtime`（文件系统 mtime，Unix 秒，sync 已维护，无 schema
    变更）；**编辑条目即刷新新鲜度**视为 feature——被持续维护的条目保持新鲜；
  - fail-open：类型未知、窗口全零/非法、mtime<=0、floor 非法一律不衰减；
  - 观测：系数使条目名次变差时 hook 记 ok.log `prompt recency:` 一行、
    ok search 打 stderr（GUI 日志可按"时效"过滤）；
  - 配置 `[retrieve.recency]` enabled（默认 true）/ floor（默认 0.85）/
    windows 子表；GUI 暴露列为跟进项。
- **注意**：mtime 是文件系统 mtime——批量重格式化/迁移条目文件会整体刷新
  新鲜度（可接受，如需"取代"语义另议 superseded_by）。
- **测试**：`TestFactorBoundaries`（四类型 fresh/stale 两端 + 线性中点 +
  未知类型）/`TestFactorFailOpen`（mtime=0、floor 非法、窗口全零/长度错/
  stale<=fresh）/`TestApplyRecency`（翻名次上榜/不翻不上榜/关闭不动）/
