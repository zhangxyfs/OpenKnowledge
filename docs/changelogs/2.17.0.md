# v2.17.0 检索策略进化：泛化门控 + RRF 融合 + 时效信号 + 反馈闭环

> 核心变化：检索注入四处进化——"继续/好的"类泛化 prompt 跳过检索与 embedding 调用；
> 融合改按名次（RRF），换 embedding 模型不再需要重调 α/β；陈旧条目在近似同分时让位；
> 新增注入→采纳反馈闭环（降权默认关闭，见说明）。

- **泛化 prompt 门控**："继续""好的""ok"这类无信息量 prompt 不再跑检索——连 embedding
  网络往返都省掉。内置 21 条中英常用确认词（编译进二进制、随版本演进），GUI 引导页
  新增「泛化门控」卡片 + 短语管理弹窗可自助维护自定义短语（与内置取并集、自动去重，
  单条 ≤64 字符）；mandatory/索引/wiki 提醒等其余注入逻辑不受影响。
- **RRF 融合**：两路命中的融合从手工加权的 `α·BM25 + β·余弦` 改为 RRF（Reciprocal
  Rank Fusion，`score = Σ 1/(rrf_k + rank)`，k 默认 60）——只看名次不看分数，换
  embedding 模型后余弦分布漂移不再破坏平衡；双通道同时命中的条目两项相加，天然
  「交叉验证优先」。准入逻辑不变；`fusion = "weighted"` 可回滚旧行为；`ok search`
  分数输出改 4 位小数。
- **时效信号**：按条目文件 mtime 的新鲜度给融合分乘系数——新鲜窗口内 1.0、陈旧后
  0.85、中间线性，窗口按条目类型分（pitfall 90/365 天、note 60/180、rule/reference
  180/730）；不参与准入（陈旧不等于无关），只在近似同分时让位；编辑条目即刷新
  新鲜度，被持续维护的条目保持新鲜。
- **注入→采纳反馈闭环**：新增 `entry_events` 表记录「注入/采纳」事件——采纳 =
  本会话注入过的条目被读取（post-tool 不开库，先挂账会话状态、下次 prompt 入账）。
  30 天窗口内注入 ≥4 次且零采纳的条目降权 ×0.8（v1 只降不升）。
- **说明**：反馈降权**默认关闭**（`retrieve.feedback.enabled = false`）——现行所有
  宿主的 PostTool 钩子只派发写工具，read 不到达追踪链路，采纳信号暂恒为零，开启
  会误伤频繁注入的条目；注入/采纳事件照常记录，待 read 派发接通后的版本恢复默认
  开启。其余三个特性默认开启；要旧排序行为显式 `fusion = "weighted"`。
